How to use this

  • One step at a time. Finish it, check the "you should see" line, tick it. If what you see differs, stop at that step and use its "If it fails" line.
  • Commands are one per box. Copy one box, paste it into the terminal (Ctrl+Shift+V), press Enter, wait for the prompt to come back, then the next box.
  • Anything that says sudo asks for your Ubuntu password. Typing it shows nothing on screen. That is normal.
  • Files you edit open in nano. Save with Ctrl+O then Enter, quit with Ctrl+X. Arrow keys move the cursor.
  • Everything gets logged into ~/theosis-kit/logs. Part K copies the logs to Windows so Claude can read them in the next Windows session.
  • Claude on Ubuntu. Claude Code is already installed on your Ubuntu (it did the 11-02 tuning). You can paste a step into it and ask it to explain or check output. It does not have the vault.
  • Badges: safe cannot break anything, your call a choice only you can make, risk can stop boot or a feature, read the undo first.

Part A · on Windows, before you reboot

Windows side

Do this now, while Claude is still running on Windows.

A1

Fix the 4 hour clock difference

your callreversible1 min

Ubuntu keeps the hardware clock in UTC. Windows reads it as Gulf time, so Windows (and WSL, and every vault timestamp) runs 4 hours slow after each Ubuntu boot. This one registry value tells Windows to read the hardware clock as UTC too. It survives any Linux reinstall, which is why the blueprint picks it over the Ubuntu-side fix.

Open Terminal (Admin): right-click Start, then Terminal (Admin). Paste:

reg add "HKLM\SYSTEM\CurrentControlSet\Control\TimeZoneInformation" /v RealTimeIsUniversal /t REG_QWORD /d 1 /f

Then fix the clock once: Settings, Time and language, Date and time, press Sync now. If Sync now is greyed out, turn "Set time automatically" off and on.

You should see "The operation completed successfully." and after Sync now the right Gulf time.
If it fails "Access is denied" means the terminal is not Admin. Reopen it as Admin.
Undo reg delete "HKLM\SYSTEM\CurrentControlSet\Control\TimeZoneInformation" /v RealTimeIsUniversal /f
The other option (not recommended)

In Ubuntu, sudo timedatectl set-local-rtc 1 makes Ubuntu keep the clock in Gulf time instead. It works because Dubai has no daylight saving, but a Linux reinstall loses it, and Ubuntu prints a warning about it. Pick one of the two, never both.

Part E · on Ubuntu

Remove what you do not use

Every package Ubuntu 26.04.1 ships by default was checked against the archive this session: what it does, and what else it would pull out if removed. Do this part in a GNOME session, before Part G. Your GNOME login stays working the whole time.

Two traps this part avoids

  • The file indexer (localsearch) cannot be uninstalled. GNOME's file manager depends on it, and removing it takes the Ubuntu session with it. It gets switched off instead.
  • The location service (geoclue) cannot be uninstalled either. Removing it removes GNOME itself and the login screen. Location gets turned off instead.

Every removal below goes through safe-purge.sh. It first asks apt what would be removed, and stops with nothing changed if the list contains anything GNOME, the login screen, Wi-Fi, the NVIDIA driver, Brave, apt, the kernel or Hyprland needs, or if apt's dry run fails or warns. Only then does apt ask you to confirm with Y.

F2

zram becomes the only swap

reversible3 min

You have two swaps: zram in RAM (about 800 MB/s, measured) and an 8 GiB swap file on the SSD (about 14 MB/s, and it stalls). With both, cold pages fill zram and hot pages get pushed to the slow file. Turning the file off and tuning the kernel for zram keeps swapping fast. systemd-oomd stays on so a full zram cannot hang the machine.

sudo cp ~/theosis-kit/etc/98-theosis-zram.conf /etc/sysctl.d/
sudo sysctl --system | grep -E 'swappiness|page-cluster|watermark'
sudo swapoff /swap.img
sudo nano /etc/fstab

In nano, find the line that starts with /swap.img and type # at its very start. Save (Ctrl+O, Enter) and quit (Ctrl+X).

swapon --show
You should see only /dev/zram0 in the list, and the sysctl line printed vm.swappiness = 180.
If swapoff hangs for a while it is moving pages back into RAM. Wait. It finishes.
Undo remove the # in fstab, sudo swapon /swap.img, sudo rm /etc/sysctl.d/98-theosis-zram.conf, sudo sysctl --system.
F3

Fewer disk writes: mount options

risk: a typo stops boot5 min

Three changes in /etc/fstab. noatime stops a disk write every time a file is read. lazytime batches timestamp writes. errors=remount-ro protects the disk if the filesystem finds an error. The EFI partition gets umask=0077 so normal users cannot read boot files (install finding, 11-02).

sudo cp /etc/fstab /etc/fstab.bak-theosis
sudo nano /etc/fstab
  1. On the line whose second column is / (type ext4): the fourth column holds the options, often defaults. Replace it with defaults,noatime,lazytime,errors=remount-ro. No spaces inside the options.
  2. On the line whose second column is /boot/efi (type vfat): replace its options with umask=0077.
  3. Save and quit.
sudo findmnt --verify
sudo systemctl daemon-reload
sudo mount -o remount /
findmnt -no OPTIONS /
You should see "0 parse errors" from findmnt --verify (warnings about swap are fine), and the options for / include noatime,lazytime. The EFI change applies at the next boot.
If findmnt --verify reports an error do not reboot. Run sudo cp /etc/fstab.bak-theosis /etc/fstab and try the edit again.
If the laptop does not boot after this boot the USB, choose Try Ubuntu, open a terminal, run sudo mount /dev/nvme0n1p6 /mnt then sudo cp /mnt/etc/fstab.bak-theosis /mnt/etc/fstab, reboot.
F4

The agent memory box

reversible5 min

Right now each Claude session has its own 12 GB cap (C09), but if any program inside a session runs out of memory, the whole session is killed. This step does two things:

  • All agent sessions share one box (agents.slice) sized to what is free when only the desktop and Brave are open. The desktop can never be starved by agents. Inside the box, agents get lower CPU priority than the desktop only when both want the CPU, so the desktop never stutters.
  • Each session gets OOMPolicy=continue: a runaway build or test dies alone and the session keeps going. Tools inside a session are also capped at 6 GB each.
  • If memory stays under heavy pressure for a long time, systemd-oomd stops the one agent session causing it, never the desktop or Brave.

First close everything except the desktop and Brave (with your usual tabs). Then:

bash ~/theosis-kit/scripts/make-agents-slice.sh
mkdir -p ~/.config/theosis
cp ~/theosis-kit/user/claude-wrapper.bash ~/.config/theosis/
cp ~/.bashrc ~/.bashrc.bak-theosis
nano ~/.bashrc

In nano: find the block marked Theosis tuning C09 (Ctrl+W searches). Delete that whole block (Ctrl+K deletes a line). At the end of the file add this one line, then save and quit:

source ~/.config/theosis/claude-wrapper.bash

Open a new terminal, start claude, and in a second terminal run:

cat /proc/$(pgrep -n -x claude)/cgroup
You should see a path containing agents.slice/run- and ending in .scope. The script also printed the box size, for example MemoryMax=16000M (yours is whatever was free).
If the path has no agents.slice the old C09 block is still in .bashrc, or you started claude in a terminal opened before the edit.
Undo cp ~/.bashrc.bak-theosis ~/.bashrc and rm ~/.config/systemd/user/agents.slice.

safe

Not in this guide, on purpose

Campus Wi-Fi password: who keeps it

your callreversible2 min

Give each GPU a fixed name

reversible1 min

Your laptop panel is wired to the Intel Arc and the HDMI port to the RTX 4060 (measured 11-03). Hyprland must draw on the Intel one. The script finds both GPUs and creates two fixed names, /dev/dri/intel-igpu and /dev/dri/nvidia-dgpu, because the plain card numbers can swap between boots.

bash ~/theosis-kit/scripts/make-dri-rules.sh
You should see two lines like /dev/dri/intel-igpu -> card1 and /dev/dri/nvidia-dgpu -> card0. The numbers do not matter.
Undo sudo rm /etc/udev/rules.d/95-theosis-dri.rules
G5

Put the configs in place

reversible3 min

Three Hyprland files plus two small environment files. The environment files tell Hyprland to use the Intel GPU and set cursor size. They live outside the Lua file, as the Hyprland wiki asks for uwsm sessions.

mkdir -p ~/.config/hypr ~/.config/uwsm ~/Pictures/Screenshots
cp ~/theosis-kit/hypr/hyprland.lua ~/theosis-kit/hypr/hypridle.conf ~/theosis-kit/hypr/hyprlock.conf ~/.config/hypr/
cp ~/theosis-kit/hypr/uwsm/env ~/theosis-kit/hypr/uwsm/env-hyprland ~/.config/uwsm/
nano ~/.config/hypr/hyprland.lua

At the top, under CHOICES: set kbLayout to the layout from your inventory (localectl status, the "X11 Layout" line, for example "us" or "gb"). Leave the rest. Save and quit.

G6

Check the config before logging in

read only1 min

The config was checked against the 0.57.1 source code, but this is its first run on a real Hyprland. These two checks catch mistakes without starting Hyprland.

luac5.4 -p ~/.config/hypr/hyprland.lua
Hyprland --verify-config -c ~/.config/hypr/hyprland.lua 2>&1 | tee ~/theosis-kit/logs/hypr-verify.txt
You should see nothing from luac (no news is good news), and config ok at the end of the second.
If it lists errors do not log in to Hyprland yet. The log is saved. Paste the errors into Claude on Ubuntu (it can fix Lua), or bring the log back to Windows with Part K.

Part H · on Ubuntu

Agent stack

H1

Claude Code sandbox

reversible3 min

Claude Code's sandbox needs two packages. Ubuntu blocks the sandbox tool by default, so this step adds the AppArmor profile from Claude Code's own docs. It allows only that one program, the rest of the system keeps the protection.

sudo apt install bubblewrap socat
which bwrap
sudo cp ~/theosis-kit/etc/bwrap /etc/apparmor.d/bwrap
sudo systemctl reload apparmor

Restart Claude Code and type /sandbox in it.

You should see /usr/bin/bwrap from which, and /sandbox shows the sandbox as available.
If which shows a different path the profile does not apply. Tell Claude on Windows next session.
Undo sudo rm /etc/apparmor.d/bwrap, sudo systemctl reload apparmor.
H2

Python and Node tooling

reversible3 min

uv runs Python projects and installs packages many times faster than pip. mise manages Node versions. Shims mode keeps shell start fast (0.30 s to 0.04 s measured on WSL). Node 26 is the current LTS.

curl -LsSf https://astral.sh/uv/install.sh | sh
curl https://mise.run | sh
echo 'eval "$(~/.local/bin/mise activate bash --shims)"' >> ~/.bashrc

Open a new terminal:

mise use -g node@26
node --version
uv --version
You should see a v26. Node version and a uv version.
Undo delete ~/.local/bin/uv, ~/.local/bin/mise and the mise line in .bashrc.
H3

Tailscale, mosh and tmux

reversible5 min

Puts Ubuntu on your tailnet so your phone can reach it (the same phone door you use on WSL), and mosh keeps the phone session alive over bad Wi-Fi.

sudo apt install mosh tmux
curl -fsSL https://tailscale.com/install.sh | sh
sudo tailscale up --ssh

It prints a login link. Open it in Brave and log in with the same GitHub account as your other nodes. Then:

tailscale status
You should see this machine plus your phone and the WSL node in the list.
Undo sudo tailscale down, sudo apt remove tailscale.

The firewall (ufw) is parked by you for now. It is not in this guide. Codex, OpenCode and the cswap account switcher go in a later session.

Part I · on Ubuntu

Reboots from Linux come back to Linux

I1

Keep Windows as default, but return to Linux on purpose

your callreversible5 min

GRUB boots Windows by default (your choice). So a reboot started from Linux, for example from your phone over Tailscale, lands in Windows and the phone door dies. This lets Linux say "next boot only: Ubuntu", while a normal cold boot still goes to Windows. Skip this step if you do not want it.

sudo cp /etc/default/grub /etc/default/grub.bak-theosis
sudo nano /etc/default/grub

Change the GRUB_DEFAULT= line to GRUB_DEFAULT=saved. Save and quit. Then find the exact Windows entry name in your inventory (search menuentry), it looks like Windows Boot Manager (on /dev/nvme0n1p1):

sudo update-grub
sudo grub-set-default "Windows Boot Manager (on /dev/nvme0n1p1)"
echo "alias reboot-linux='sudo grub-reboot Ubuntu && sudo reboot'" >> ~/.bashrc
You should see a cold boot still goes to Windows, and reboot-linux in a new terminal reboots straight into Ubuntu.
Undo sudo cp /etc/default/grub.bak-theosis /etc/default/grub, sudo update-grub, delete the alias line in .bashrc.
Part J · Windows, BIOS, then Ubuntu

VMD off, last

This ends the 30 second SSD freezes that hit about half of your boots (Intel erratum MTL016). You moved it to the end. It needs one Safe Mode boot of Windows. Only do it if Part B found the VMD switch.

J1

Prepare Windows

risk: read all of Part J first2 min

Without this, Windows would crash at boot (INACCESSIBLE_BOOT_DEVICE) after VMD goes off, because it only loaded the VMD storage driver. Safe Mode makes it load the plain NVMe driver once. In Windows Terminal (Admin):

manage-bde -status C:
bcdedit /set {current} safeboot minimal
You should see "Fully Decrypted" and "Protection Off" from manage-bde (BitLocker must be off), then "The operation completed successfully."
If BitLocker is on stop here and tell Claude on Windows.
J2

Switch VMD off in the BIOS

risk3 min
  1. Restart. Tap F2 at the ASUS logo. Press F7.
  2. Advanced tab, the VMD menu you found in Part B. Set the VMD controller to Disabled.
  3. Press F10, confirm Save and Exit.
  4. In GRUB pick Windows Boot Manager. Windows starts in Safe Mode (black background, "Safe Mode" in the corners). Log in, with your password if the PIN is refused.
J3

Leave Safe Mode

2 min

In Safe Mode, open Terminal (Admin) and run:

bcdedit /deletevalue {current} safeboot

Restart, pick Windows again. Windows boots normally. Launch VALORANT once to check Vanguard is happy.

You should see a normal Windows desktop and VALORANT reaching its menu.
If Windows will not boot at all F2, F7, set VMD back to Enabled, F10. Windows boots again (into Safe Mode if the safeboot value is still set, then run the J3 command).
J4

Check Ubuntu after VMD off

5 min

Restart and pick Ubuntu in GRUB. If GRUB does not appear and the laptop goes straight to Windows, see "If it fails". In Ubuntu:

lsblk
sudo efibootmgr -v | tee ~/theosis-kit/logs/after-vmd-efibootmgr.txt
journalctl -k -b | grep -c "completion polled"
bash ~/projects/tuning/bench/verify-all.sh | tee ~/theosis-kit/logs/after-vmd-verify.txt
You should see the disk still named nvme0n1, an "ubuntu" entry in efibootmgr, 0 from the grep, and all PASS. Over the next 10 boots, run the grep once per boot. The target is 0 every time (before: about half of boots had a 30 s freeze).
If the laptop skips GRUB tap Esc at power on, choose "Enter Setup" or the boot file option, browse to EFI/ubuntu/shimx64.efi. Once in Ubuntu, check lsblk shows nvme0n1 with partition 1 as the EFI one, then run sudo efibootmgr -c -d /dev/nvme0n1 -p 1 -L ubuntu -l '\EFI\ubuntu\shimx64.efi'.
